## 忆古 — 线路一：深度交互推演

### 项目背景

**忆古（Yigu）** 是一个 AI 驱动的文化遗产设计与叙事交互平台。当浏览者输入一件古器物的名称，系统从"形·质·时"三个维度拆解它的设计逻辑——不是给百科信息，而是回答"它为什么长成这样"。

当前网页已完成基础骨架：
- 单页 HTML（`yigu-preview/index.html`，约 23KB）
- 深色墨韵色调（`--bg-deep: #0A0806`，金色点缀 `#C9A96E`）
- 页面结构：Hero（含搜索框）→ 概念页（"不是百科全书，是一次拜访"）→ 形·质·时三支柱 → 金句 CTA → 搜索结果（器物卡片 + 三条分析 + 导出按钮）
- 数据库：3 件文物（建窑兔毫盏、马家窑彩陶罐、汝窑天青釉弦纹樽），每件 3 条分析
- 已有交互：搜索输入 → 回车/点击提示词 → 展示结果；返回按钮；Escape 键返回；滚动进度条；parallax 视差
- Git 已关联 GitHub：`jennymcgregor627-jpg/yigu-portfolio`

### 当前问题

现有交互是一条**单向线性路径**：
```
Hero → 概念页 → 形·质·时 → CTA → 搜索 → 一次性全量渲染结果
```
所有分析内容一次性堆出来，没有"推演"的感觉。浏览者无法：
- 按自己的兴趣权重看到不同排序
- 在器物之间跳转对比
- 用浏览器前进/后退
- 分享当前浏览状态

### 目标

将页面从"展示结果"升级为**推演式的交互体验**——浏览者感觉自己正在一层层深入，而不是被喂了一堆文字。

## 开发计划

### 第一阶段：浏览者状态系统（兴趣锚点）

**核心思路**：浏览者在形·质·时三个 pinned 页面中的滚动停留时长，决定了进入搜索结果后三条分析的默认排序。

**具体任务**：

1. 给三个 pinned-section 分别添加 `data-anchor` 属性（`form`、`material`、`time`）
2. 用 `IntersectionObserver` 追踪每个页面在视口中的停留时长
3. 将累计时长写入 `sessionStorage`（key: `yigu-anchors`）
4. 在 `buildResults()` 函数中读取 anchor 数据，重新排序 `analyses` 数组：
   - 如果在"质"页面停留最久，关于釉料/材质的分析排到第一位

**涉及文件**：`yigu-preview/index.html`（JS 部分）

**验收标准**：在"质"页多停留几秒，搜索后第一条分析是材质相关的内容。

---

### 第二阶段：推演式结果页重构

**核心思路**：搜索结果不再一次性全量渲染，而是**分三阶段释放**。

**具体任务**：

1. 改写 `buildResults()`：
   - Phase 1：器物卡片 + 第一条分析（默认"形"相关），带入场动画（`opacity` + `translateY` 渐入）
   - Phase 2：滚动触发第二条分析切入（`IntersectionObserver` 监听第一条分析的底部）
   - Phase 3：滚动触发第三条分析切入
2. 三条分析之间的**关联线**：
   - 在分析文本中找到共同的线索词（如"铁元素"在兔毫盏的前两条分析中都出现）
   - 用内联 SVG 画一条金色的细连线，从第一条分析的关键词标注连接到第二条
3. 底部 CTA 改造：
   - 不再只是"导出 SVG"
   - 改为横向滚动的**推荐卡片**：展示另外两件器物的同维度分析预览
   - 卡片可点击，跳转进入该器物的分析流

**涉及文件**：`yigu-preview/index.html`（JS + CSS）

**验收标准**：
- 搜索"建窑兔毫盏"，先看到器物卡片 + 一条分析
- 向下滚动，第二、第三条依次出现
- 底部出现横向滚动的推荐卡片

---

### 第三阶段：探索模式 vs 讲解模式

**核心思路**：页面顶栏增加一个双态开关，两种模式切换。

**具体任务**：

1. 在页面顶部固定栏（跟随滚动）添加一个双态开关：
   - **讲解模式**（默认）：当前的线性叙事流，适合第一次看
   - **探索模式**：把三件文物以卡片阵列展示，每张卡片展示"名称 + 时代 + 一个最抓人的问题"
2. 探索模式卡片阵：
   - Grid 或 Masonry 布局
   - 每张卡片 hover 时浮动微升，点击进入该器物的分析流
   - 分析流中同样有返回按钮，回到探索卡片阵
3. 模式切换动画：页面内容 crossfade 过渡

**涉及文件**：`yigu-preview/index.html`

**验收标准**：点击切换，页面从叙事流变为卡片阵，卡片可点击进入分析。

---

### 第四阶段：制式对比视图

**核心思路**：在探索模式下选中两件器物，并排展示同维度分析。

**具体任务**：

1. 探索模式卡片阵中，每张卡片增加一个"对比"勾选框
2. 选中两件后，底部浮现"并排对比"按钮
3. 对比视图：
   - 左右分栏，各展示一件器物的同维度分析
   - 中间用竖线分隔，顶部标注共同主题（如"釉的化学"、"口沿的人因工程"）
4. 支持在对比视图中切换维度（形/质/时）

**涉及文件**：`yigu-preview/index.html`

**验收标准**：选中两件器物后并排展示同维度分析，中间有关键词标注。

---

### 第五阶段：URL 状态与分享

**核心思路**：每次跳转反映在 URL 中，浏览者可用浏览器前进/后退，链接可分享。

**具体任务**：

1. 每次进入分析页时 `history.pushState({...}, '', '?q=建窑兔毫盏&step=2')`
2. 监听 `popstate` 事件，恢复对应的浏览状态
3. 特殊处理：
   - 不带参数的 URL 回到 Hero 页
   - `?mode=explore` 直接进入探索模式
4. 分享链接时，接收者看到相同的器物和步骤

**涉及文件**：`yigu-preview/index.html`

**验收标准**：浏览器前进/后退按钮可用，URL 参数可复制分享。

---

## 阶段依赖关系

```
第一阶段（状态系统）→ 第二阶段（推演式渲染）→ 第三阶段（模式切换）
                                                   ↓
                                          第四阶段（对比视图）
                                                   ↓
                                          第五阶段（URL 状态）
```

第三阶段以后的模块可以相对独立开发，但建议按顺序推进。

---

## 技术注意事项

- 所有代码在一个 HTML 文件中（内嵌 CSS + JS），不引入额外依赖
- 保持现有的深色墨韵主题和金色点缀色彩系统
- 字体使用 Google Fonts 的 Noto Serif SC + Noto Sans SC
- 交互必须支持键盘操作（Escape、Tab）
- SEO 不考虑，但页面应支持 `history.pushState` 以保证浏览器行为正常
